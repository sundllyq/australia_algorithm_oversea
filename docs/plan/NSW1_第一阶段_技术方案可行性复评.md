## 1. 总体结论

**方案总体可行，建议进入实施。** 方法论严谨度高于一般第一阶段研究要求，与 `AGENTS.md` 及各上位契约无冲突。

可行性风险不在方法论，而集中在三类现实问题：

1. **数据不确定性（方案已正确设防）**：P5MIN 历史 vintage 完整性与可见时间只能经 E0 数据审计确认，这是全案最大的不可预先消除的不确定性；
2. **三个重计算环节缺量级估算**：rolling-origin PIT 模板、12 个月逐 5 分钟 MILP 滚动回放、V1 终端价值延续优化，按字面执行均不可行，需要方案内显式的抽样/降载规则；
3. **工程复杂度**：血缘与 manifest 字段面很大，需按里程碑分批实现，避免拖慢首个可验收证据（E1–E3）。

上述第 2、3 类问题均可通过小规模增量修订解决，不构成推翻方案的理由。

## 3. 方法论可行性：设计合理的部分

以下环节经评估认为方法正确、可实施，无需修改：

- **范围收敛**：从"五区域 × 24 小时 × 在线 EMS"收敛到"NSW1 × 未来 60 分钟 × 离线研究"，与仓库现状（零代码）和第一阶段契约一致；
- **Point-in-time 体系**：available time 代理、vintage 全保留、snapshot 选择规则、快速失败清单，构成完整防泄漏设计；
- **锚点残差建模** Y = A + E：以 P5MIN 为锚点学习条件残差分布，M0 条件经验残差作必须击败的基线——统计上正确，且 M0 计算廉价，保证 E1 能尽早交付首个可验收概率能力；
- **样本量充足性**：每年约 10.5 万个决策时点 × 12 horizon ≈ 126 万训练行/年，LightGBM pooled 分位数模型在算力上无压力；
- **路径方法公平比较**：J0/J1/J2/J3 共享边际样本隔离依赖结构贡献、边际多重集硬不变量、§7.11 可证伪关系（风险中性 open-loop 下重排不应改变首动作）——这是高质量的行为测试设计；
- **信息结构对照**：O0/O1/O2 的单调性关系 O2 ≥ O1 ≥ O0 提供了优化器正确性的可检验边界；non-anticipativity 以前缀嵌套实现，正确；
- **终端价值分层**：V0 诊断 / V1 历史价值表 / V2 数据门控 challenger，且明确承认 V1 含完美预知偏乐观并给出折扣与 rollout 敏感性处理——态度诚实；
- **统计纪律**：配对 block bootstrap、独立 episode 披露、预注册非劣效界限、多重比较控制、负结果接受与停止条件，均符合研究规范；
- **champion/challenger 晋升机制**：不预设条件重排或复杂模型为冠军，以证据晋升——有效防范复杂度崇拜。

## 4. 可行性风险分级评估

### 4.1 高风险：三个重计算环节缺量级估算

**R1. rolling-origin PIT 模板构建成本。** J2/J3 要求每个历史起点有 as-of CDF。训练期约 3 年 ≈ 31 万个起点，每点 12 horizon。若模板 CDF 取自 M0 条件经验残差，是纯查表，成本可控；若要求与 M1 LightGBM 校准分布版本兼容，逐起点重训不可行。方案 §7.8 有降级路径（先跑 J0/J1），但未给出简化规则。建议：明确首版模板 CDF 只使用**按月冻结的模型快照版本**（每月重训一次 + 批量推断），逐起点 rolling-origin 降级为抽样审计。

**R2. 12 个月逐 5 分钟 MILP 回放的求解预算。** 测试期 ≈ 105,120 个决策点。O1 多阶段树 + S=100 场景 + 方向二进制的 MILP，按每次 1–3 秒估算，单策略单费用情景需 30–90 CPU 小时；乘以策略（C3/C4/C5）× 路径方法（J0–J3）× 费用情景（4 档）× 视野敏感性（3 档），总量轻易达到数千 CPU 小时。方案只要求报告求解时间，未给出总预算或降载设计。建议采用两级结构：**全量 12 个月只跑冻结主配置（每路径方法一个 C3/C4/C5 主组合）；完整因子矩阵只在分层抽样子期**（普通日 / 负价日 / 尖峰日 / 高波动日）上运行。同时在 M0 增加约 50 个决策点的微型端到端回放基准，尽早实测单次求解时间并据此反推可行的 S 与树复杂度上限。

**R3. V1 终端价值表的延续优化规模。** 方案 §9.4.1 字面要求"对 Train 中每个历史窗口结束时点 × 每个 SOC 格点"求解 48 小时延续问题。3 年训练期 ≈ 31 万个窗口末 × 0.5 kWh 格点（5.0–22.5 kWh 共 36 点）≈ 1130 万次优化，不可行。必须显式改为**按 context（时段 × 日型 × 季节）分层抽样窗口末**（例如每 context 桶抽数百个），将求解次数降至数千至数万次，并对抽样不确定性做敏感性说明。建议在方案 §9.4 直接写明抽样规则，防止实现时按字面执行。

### 4.2 中风险

**R4. P5MIN 历史归档完整性与可见时间。** 这是全案最大的不可预先消除的不确定性：月度归档的逐月完整率、run revision 保留、`LASTCHANGED` 语义都只能在 E0 中实测。方案的处理方式正确（E0 为第一闸门 + "无法重建可信 vintage 则停止强运营结论"的停止条件）。补充一点：月度 `PUBLIC_DVD` 文件本身次月发布，其文件时间不能作为 available time 证据，只能依赖 `LASTCHANGED`/`RUN_DATETIME` 代理或本地采集——方案 §4.4 已覆盖，维持即可。

**R5. 工程血缘面过大。** manifest / snapshot / 模板 / 场景 / 决策 / 结算各层合计上百个版本字段。对第一阶段而言，一次性实现全部字段会拖慢 M1–M2 的首个证据产出。方案 §12.1 已声明"不要求一次性创建全部目录"，建议对**字段**做同样的分批声明：M1 只需 raw 级 manifest + snapshot 键；模板、场景、终端价值的完整血缘随对应里程碑引入。

**R6. 求解器与新增依赖未验证。** 当前环境仅有 nemseer/nemosis。MILP 候选（如开源 HiGHS）对多阶段树场景规模的性能未知。方案 §12.7 已要求最小原型先行验证，正确；建议把该原型前移到 M0（与 R2 的微型回放基准合并），避免在 M5 才发现求解预算不满足。

### 4.3 低风险（方案已充分覆盖）

- 极端事件样本稀少 → episode 披露、层级收缩、压力场景分离；
- 市场 floor/cap 历史版本变化 → 方案要求按生效期连接，不回填；
- S2 合成站点代表性 → S1/S2 分离、forecast/outcome 分层、措辞边界明确；
- 无 git 元数据 → 方案允许源码 SHA-256 替代；但直接 `git init` 成本更低，建议优先。

### 4.4 小的技术修正建议

1. **V1 延续问题的 LP/MILP 选择**：确定性完美预知价格在正常费用结构（进口价 ≤ 出口价、效率 < 1）下同时充放电无利可图，LP 松弛精确、可免二进制；但负价叠加不对称费用时该性质未必成立。建议 §9.4 增加与 §8.3 相同纪律的决策规则："先证明，再松弛"。
2. **逆 CDF 在场景分位网格上的行为**：S=500 时 q_j 覆盖 0.001–0.999，超出 P01/P99 的部分依赖尾部规则。§13.9 已有部分测试，建议在 E3 验收中显式加入"场景分位网格上逆 CDF 单调且有界"的自动化断言。
3. **锚点缺失的主样本覆盖率**：方案要求 12 个 horizon 锚点齐全方入主样本，正确；E0 若发现归档存在系统性缺 run（如维护窗口），覆盖率损失须在评价中披露——方案 §5.4 已要求，此处仅作强调。

## 5. 与上位契约的一致性

逐项比对 `AGENTS.md`、`RESEARCH_SCOPE.md`、`DATA_CONTRACT.md`、`FORECAST_PROTOCOL.md`、`BESS_BACKTEST_PROTOCOL.md`：

- 第一阶段固定契约（NSW1、5 分钟 interval-ending、12 步、概率优先、P5MIN 核心外部预测、NEMSEER/NEMOSIS 入口、Python 3.11、10 kW / 20 kWh 资产、三档显式费用）：**全部满足**；
- 时间语义、标签契约（DISPATCHPRICE/RRP/INTERVENTION=0）、基线集合（B0–B4）、评价指标体系、结算公式与费用情景纪律：**一致，方案为上位契约的细化而非冲突**；
- 未发现任何方案条款与上位契约矛盾。

## 6. 建议的最小修订清单

按优先级排序，均为增量修订，不改变方案主线：

1. 为 R1/R2/R3 三个重计算环节补充量级估算与显式降载规则（按月冻结模板模型版本、回测矩阵两级设计、V1 窗口末分层抽样）；
2. M0 增加约 50 决策点的微型端到端回放基准，尽早锁定求解器选型与单次求解时间量级；
3. 血缘/manifest 字段按里程碑分批实现，M1 只保留 raw 与 snapshot 级；
4. §9.4 明确 V1 延续问题的方向二进制/LP 松弛决策规则；
5. 优先 `git init` 建立版本控制，替代长期的 SHA-256 变通方案。

## 7. Go / No-Go 建议

**Go。** 建议立即进入 M0（工程前置）与 M1（E0 数据审计）。

全案真正的 go/no-go 决策点有两个，均不应跳过：

1. **E0 数据审计**：P5MIN vintage 逐月完整率与可见时间代理是否成立——决定残差建模与公平基线比较的可行性；
2. **M5 前的两次算力基准**：PIT 模板构建成本与 MILP 逐点求解时间——决定随机 MPC 主比较的规模上限。

若两处闸门任一不通过，方案的停止条件（§14.2）已给出对应的降级路径，研究仍能以更简单的方法组合交付有效结论。
