# PIT 模板、随机化和历史快照

> 教学说明，不新增主方案契约。正式模板字段、资格、兼容和 Test 冻结规则以主技术方案第 7.5、7.8 节为准。

## 1. PIT 是什么

概率积分变换（Probability Integral Transform, PIT）把历史实际价格转换为它在当时预测分布中的位置：

```math
u_{i,h}=F^{asof}_{i,h}(y_{i,h})
```

- $F^{asof}_{i,h}$：历史起点当时可生成的 CDF；
- $y_{i,h}$：后来实现并可见的 NSW1 RRP；
- $u_{i,h}$：实际结果在当时预测分布中的累计概率位置。

PIT 接近 0 表示实际落在当时预测的低位，接近 1 表示落在高位。PIT 不是价格，也不是预测准确率。

## 2. 为什么需要随机化 PIT

若预测分布在某个精确价格上有点质量，CDF 会跳跃。例如：

```text
P(Y<0)=30%, P(Y=0)=20%, P(Y>0)=50%
```

若实际价格正好为 0，普通 PIT 会把所有这类样本放在 $F(0)=0.50$，产生堆积。随机化 PIT 在跳跃区间内取一个位置：

```math
u=F(y^-)+v\,[F(y)-F(y^-)],\qquad v\sim U(0,1)
```

其中 $F(y^-)$ 是左极限。随机的是点质量内部的概率位置，不是把实际价格改掉。

## 3. 为什么用固定哈希生成 v

理论上 $v$ 是随机数；工程上同一实验必须可复现。因此用稳定键生成确定性伪随机比例：

```text
template_id + horizon + pit_method_version -> 固定哈希 -> v in (0,1)
```

这保证同一模板同一 horizon 重放时得到同一个 $v$，而不同模板或不同 horizon 通常得到不同位置。不能使用 Python 内置 `hash(text)`，因为它跨进程不保证稳定。

## 4. 为什么五分钟保存模板

相邻五分钟起点的一小时窗口高度重叠，但 PIT 不一定重复：同一个目标区间在不同起点对应不同 horizon、不同 P5MIN vintage、不同可见特征和不同 CDF。

因此存储层保留所有合格五分钟起点；使用层再通过起点间隔、市场日上限和 episode 上限控制重复贡献；统计层用 block bootstrap 和 episode 分块处理相关性。

## 5. 为什么需要 as-of 历史快照

PIT 必须使用历史起点当时可生成的 CDF，不能用最终模型回算全历史。没有归档预测分布时，需要按 rolling-origin 方式构建月度完整预测快照：

```text
生效前允许的历史 -> 拟合模型/校准器/CDF 组件 -> 生效期内批量推断 -> 结果揭晓后计算 PIT
```

月度快照控制的是信息边界和计算成本：同一个已生效快照可以服务整个月的五分钟起点，但不能在月末训练后回头预测月初。

## 6. family 与 snapshot 的区别

- `forecast_cdf_family_version`：方法规范，类似菜谱；
- `forecast_snapshot_id`：某次按该方法拟合出的完整流水线，类似某一锅；
- `forecast_distribution_id`：某个起点输入经快照生成的具体 CDF。

同一 family 下不同月份可以有不同参数；跨 family 混用 PIT 默认禁止，除非通过预注册兼容性回放。
