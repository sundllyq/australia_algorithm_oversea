# 时间切分、滚动起点、Embargo 与 Test 冻结

> 本文是主技术方案 [§4.9 时间切分](../NSW1_第一阶段_一小时残差概率预测与储能随机滚动优化技术方案.md#49-时间切分) 的教学性解释，用于帮助理解，不新增实验契约。如与主方案冲突，以主方案为准。下文日期仅为手算示例，真实边界必须由数据审计冻结并写入实验配置。

## 1. 一句话理解四个阶段

```text
Train -> Validation -> Calibration -> Test
 学习       选择          校刻度        封卷考试
```

- Train 从过去学习模型参数和训练期统计量。
- Validation 比较候选方法，决定使用哪个模型、特征、窗口和规则。
- Calibration 不再换模型，而是把已选模型的分位数、事件概率以及 V1 允许的终端价值折扣/收缩调到可解释的尺度。
- Test 只评价冻结系统，不再让任何 Test 标签改变模型、校准器、模板库或选择规则。

Embargo 不是第五个学习阶段，而是相邻阶段之间主动丢弃的时间隔离带，用来阻止一小时标签窗口跨过边界。

## 2. 示例的时间口径

假设 E0 数据审计确认：

- 共同可用历史从 2021-10-01 开始；
- 2025 年 12 个月是最新完整的 Test 起点月份；
- 数据至少覆盖到 2026-01-01 00:55 AEST，以便 2025-12-31 23:55 起点的 `h=12` 标签也已揭晓并通过资格检查；
- 主 horizon 为 60 分钟，步长为 5 分钟，`h=1...12`；
- 市场时间使用固定 UTC+10 的 AEST，标签采用 interval-ending 语义。

下文表中的时间是 `model_issue_time_aest=t`。每轮真正能够读取的数据仍受以下条件限制：

```text
decision_cutoff_aest = t - decision_delay_seconds
source_available_at_aest <= decision_cutoff_aest
```

因此，把一条记录放在历史文件中，不等于它在当时的预测起点已经可用。

## 3. 一套完整日期切分

| 区段 | 示例起点范围 | 在本例中的作用 |
|---|---|---|
| Train | 2021-10-01 00:00 – 2023-06-30 22:55 | 拟合基础模型与 Train-only 统计量 |
| Embargo | 2023-06-30 23:00 – 23:55 | 丢弃跨入 Validation 边界的起点 |
| Validation | 2023-07-01 00:00 – 2023-12-31 22:55 | 比较并选定模型、特征、窗口和规则 |
| Embargo | 2023-12-31 23:00 – 23:55 | 丢弃跨入 Calibration 边界的起点 |
| Calibration | 2024-01-01 00:00 – 2024-12-31 22:55 | 拟合最终概率校准与 V1 允许的终端折扣/收缩 |
| Embargo | 2024-12-31 23:00 – 23:55 | 防止 Calibration 标签跨入 Test |
| Test | 2025-01-01 00:00 – 2025-12-31 23:55 | 使用已冻结系统完成一次主滚动评价 |

Validation 取六个月、Calibration 取十二个月只是为了让例子完整，不是项目预设长度。真实窗口需由数据量、尖峰/负价事件支持度和校准稳定性决定，并在查看 Test 结果前冻结。

## 4. 每个阶段具体做什么

### 4.1 Train：学习模型参数

对于每个训练起点 `t`，只使用在 `decision_cutoff_aest` 前可见的 P5MIN vintage、近期 NSW1 RRP、供需/网络特征和质量标志，建立 12 个目标：

```text
h=1  -> t+5 分钟的 interval-ending NSW1 RRP
h=2  -> t+10 分钟的 interval-ending NSW1 RRP
...
h=12 -> t+60 分钟的 interval-ending NSW1 RRP
```

Train 拟合：

- 特征填补、类别字典和仅限 Train 的统计量；
- B3/M0 条件经验残差分布；
- M1 残差分位数模型；
- M2 负价/高价事件模型；
- 如果启用 V1，则使用 Train 历史构建原始终端价值表。

候选超参数可以对应多次 Train 拟合，但这些拟合始终不能读取 Validation、Calibration 或 Test 标签。

### 4.2 Validation：选择候选方案

在 Validation 上比较 Train 产生的候选，例如：

- P5MIN+近期 RRP 与再加供需/网络特征的特征组；
- 不同 LightGBM 结构、训练窗口和 ensemble 规则；
- B3 状态划分、最小样本数、回退层级和收缩规则；
- J0/J1/J2/J3 晋升路线、场景数和条件检索规则；
- 终端价值 context、延续窗口、SOC 网格与候选折扣方案。

选择依据是分 horizon pinball/WIS、覆盖率与区间宽度、事件 Brier score、稳定性和预注册的运营验证指标，不能因为某几个尖峰日收益更高就临时换方案。

Validation 结束后，用 Train 重新生成已选结构的最终基础模型并冻结，不把 Validation 标签合并进基础模型拟合。如果未来要研究 Train+Validation 重拟合，需要单独的预注册快照和时间外 Calibration 生成规则，不能默认混入本例。

### 4.3 Calibration：校准概率尺度

已冻结基础模型先对 Calibration 起点生成不读取当期标签的原始预测，等结果揭晓后再用这些“时间外预测+实现值”拟合校准器。

例如，下列数字仅用于说明校准含义，不是项目结果：

- 名义 P10–P90 区间应覆盖约 80% 实现值，原始模型只覆盖 72%；
- 原始模型给出负价概率 30% 的样本中，实际只有约 20% 发生负价。

校准器的作用是修正这些概率刻度，同时拟合 V1 允许的终端价值统一折扣或层级收缩；V2 折扣仍在 Validation 冻结。Calibration 不应再决定特征集、模型深度或场景方法；否则它已经被当成第二个 Validation。

### 4.4 Test：冻结后完成样本外评价

进入 Test 前冻结：

- 基础模型、特征 schema 和特征处理参数；
- 概率校准器、事件阈值和 CDF 构造规则；
- 场景生成、风险、优化和终端价值配置；
- PIT/残差模板库成员、内容哈希和治理元数据；
- 资产、站点、费用、退化、指标和评价边界。

Test 的实际价格可以用于当期结算和最终评分，但不能反馈到任何冻结产物中。如果团队反复查看 Test 并据此改方法，该 Test 就已变成探索集，必须保留新的 untouched holdout 才能恢复强结论。

## 5. Embargo 的 60 分钟手算

设 Validation 第一个起点为：

```text
B = 2023-07-01 00:00 AEST
```

如果 Train 保留以下起点：

```text
t = 2023-06-30 23:55
```

它的 `h=12` 目标是 2023-07-01 00:55，已经落入 Validation 时间。因此，本例排除：

```text
2023-06-30 23:00, 23:05, ..., 23:55
```

共 12 个五分钟起点。最后一个合格 Train 起点为 22:55，其 `h=12` 目标为 23:55，不再触及 Validation 边界。

可以把排除规则理解为：

```text
若前一段某起点的任一 target_interval_end
>= 后一段首个 model_issue_time，则排除该起点。
```

若评估 120 分钟 horizon，同一边界需至少排除 22:00–23:55 的 24 个起点，最后合格起点变为 21:55。

上述只是按 horizon 计算的最小隔离。如果 23:55 的实际结果要到更晚才满足 `outcome_available_at_aest`，则还要扩大隔离；不能把 nominal time 当成结果已可用的证据。

## 6. Test 前两轮五分钟回放

### 6.1 第一轮：`t=2025-01-01 00:00`

1. 计算 `decision_cutoff=t-decision_delay_seconds`。
2. 只释放 `available_at <= decision_cutoff` 的 P5MIN 和市场/站点输入。
3. 为 00:05、00:10、…、01:00 生成 `h=1...12` 的校准 NSW1 概率分布。
4. 使用冻结模板库构建价格路径，根据当前 SOC 求解十二步随机 MPC。
5. 只执行 `(00:00,00:05]` 的第一步动作，后 11 步只用于评估当前动作的机会成本。
6. 区间结束后使用冻结价格版本下的实际 RRP 和物理结果更新 SOC/NMI 并结算。

### 6.2 第二轮：`t=2025-01-01 00:05`

系统丢弃上一轮尚未执行的 11 步计划，读取新 cutoff 前可见的 P5MIN、市场状态和已更新 SOC，重新预测 00:10、00:15、…、01:05，并只执行 `(00:05,00:10]` 的新首动作。

两轮预测共有 11 个重叠 target，这是五分钟滚动 MPC 的正常结构，不是重复执行。预测输入和 SOC 会更新，但模型权重、校准器、模板库内容和选择规则不会更新。

## 7. 三类容易混淆的流程

| 流程 | 它真正做的事 | Test 中是否学习 |
|---|---|---|
| 主预测流水线 | 每五分钟对当前可见输入生成新概率分布 | 否；仅输入和输出变化 |
| 历史 PIT/残差库构建 | 用严格 rolling-origin 月度快照产生当时真正可生成的历史 CDF/PIT/残差路径 | 否；进入 Test 前冻结成员和内容 |
| 在线更新研究 | 模拟未来按月/按周重训、重校准或增库 | 可以，但必须是另一实验并保留独立 holdout |

例如，给 2023-01 构建 PIT 月度快照时：

1. 只使用快照生效前已可见的拟合、内部选择和校准数据；
2. 在 2023-01 内按当时信息集批量生成 CDF；
3. 等完整实际路径和治理信息揭晓后计算 PIT；
4. 只有满足完整 horizon、资格时间、价格版本和质检规则的模板才能入库。

不能用 2024 年甚至 Test 前才完成的最终模型和全年校准器回算 2023-01，再声称这是 2023-01 当时可生成的预测。进入 Test 前应对模板库生成不可变 `template_library_id` 和内容清单哈希。Test 期可以根据当前 context 选出不同历史模板，但不能把新揭晓的 Test 尖峰追加入库。

## 8. 常见错误检查

| 错误 | 为什么有问题 |
|---|---|
| 随机打乱后分 Train/Test | 相邻五分钟起点共享大量 target 和市场状态，会把未来泄露进训练 |
| 只按文件所在月判断 Test 完整 | 月末起点的 `h=12` 可能已跨入下月/下一年，必须检查全部标签和资格时间 |
| 没有 embargo | 前一段的一小时标签窗口会跨进后一段 |
| 在 Calibration 上继续挑模型 | Calibration 已被变相当成 Validation，校准证据不再独立 |
| 看 Test 收益后调风险参数 | Test 被用于选型，不再是样本外证据 |
| 每五分钟读取新 P5MIN 就称为“在线学习” | 这只是冻结模型的新输入推断，模型参数并没有更新 |
| 用最终模型回填整段历史 PIT | 把后期模型选择和校准信息伪装成早期 as-of 预测 |
| 把 Test 新尖峰加入冻结模板库 | 后续 Test 决策已间接学习了 Test 结果 |

## 9. 最小记忆表

| 阶段 | 可以改变什么 | 不可以做什么 |
|---|---|---|
| Train | 基础模型权重、经验分布和 Train-only 处理参数 | 读取后续阶段标签 |
| Validation | 选择模型、特征、窗口、超参数和规则 | 直接拟合最终基础模型或校准器参数 |
| Calibration | 概率刻度、事件校准、层级收缩和 V1 允许的终端价值折扣 | 继续换特征、模型或场景方法 |
| Test | 只更新当时可见输入、SOC、本轮预测和首动作 | 重训、重校准、调参、增库或改评价边界 |

简化记忆是：Train 学规律，Validation 选方案，Calibration 校概率，Test 冻结回放；Embargo 负责阻止跨边界的未来一小时标签串入相邻阶段。
