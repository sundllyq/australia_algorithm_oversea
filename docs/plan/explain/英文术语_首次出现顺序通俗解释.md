本文是 [`NSW1_第一阶段_一小时残差概率预测与储能随机滚动优化技术方案.md`](../NSW1_第一阶段_一小时残差概率预测与储能随机滚动优化技术方案.md) 的配套阅读材料，面向第一次接触澳大利亚电力市场、概率预测或储能优化的读者。

## 1. 收录与阅读规则

- 术语大体按它们在主方案中第一次出现的章节顺序排列，同一术语只解释一次；少数在摘要中提前露出的概念，会放到首次详细展开它的功能章节，方便连续阅读。
- 收录市场、时间、数据、概率、模型、路径、优化、结算和工程领域中需要背景知识的英文词或缩写。
- 不逐个解释公式字母、普通代码关键字、配置字段名、文件路径和 Mermaid 绘图语法。
- `B0`、`M1`、`J3`、`O1` 等不是行业通用英文缩写，而是本项目内部编号，统一放在第 8 节说明。
- “通俗理解”用于帮助建立直觉；实现、统计检验和字段取值仍以主方案对应章节为准。

可以先把全方案理解成一条流水线：

```text
AEMO 历史数据
  -> 还原当时真正可见的信息
  -> 以 P5MIN 为锚点预测价格不确定性
  -> 把 12 个时点连成多条可能路径
  -> 每五分钟重新优化电池动作
  -> 按实际 RRP、NMI 能量和费用回放结算
  -> 判断预测改善是否真的转化为样本外运营价值
```

## 2. 首见于标题、文档首页与执行摘要的术语

| 术语 | 英文全称或直译 | 通俗理解及本项目含义 |
|---|---|---|
| `NSW1` | New South Wales region identifier | AEMO 对新南威尔士州电力市场区域使用的标识。它是区域代码，不是某个电站、用户或电池的名字；本项目的预测标签和结算价格只属于 NSW1。 |
| `RRP` | Regional Reference Price | 区域参考价格。可把它理解为 NSW1 每个五分钟区间的批发市场基准价，单位通常是 A$/MWh；它不是用户电费账单上的最终进口价或上网电价。 |
| `kW` | kilowatt | 千瓦，表示“此刻充得或放得有多快”，是功率。10 kW 连续运行 5 分钟，对应交流侧电量约 0.8333 kWh。 |
| `kWh` | kilowatt-hour | 千瓦时，表示“总共存入、取出或消耗了多少电”，是能量。20 kWh 可用能量描述容量，不描述充放电速度。 |
| `P5MIN` | 5 Minute Pre-dispatch | AEMO 的五分钟预调度短期预测产品。本方案把它当作未来一小时价格曲线的官方点预测锚点，但它本身不是 P10/P50/P90 概率预测。 |
| `forecast vintage` | forecast version issued at a particular time | “预测历史版本”。同一个目标区间会被不同时间运行的 P5MIN 多次预测，每次发行都算一个 vintage。回测必须使用决策当时已经可见的版本，不能偷换成后来更准的版本。 |
| `MPC` | Model Predictive Control | 模型预测控制。每次向前规划一段时间，但只执行眼前第一步；五分钟后根据新价格预测和新 SOC 再算一遍。像开车时持续滚动更新路线，而不是一次决定整段旅程。 |
| `AGENTS.md` | project agent instructions | 本仓库的上位规则文件，规定研究范围、固定契约、工程要求和禁止事项。它不是模型产物。 |
| `ECC` | Ensemble Copula Coupling | 集成 Copula 耦合：利用一组已有成员的排序关系，把分别校准的单时点分布重新连成多时点路径。主方案指出本项目方法更接近 PIT-based Schaake shuffle，“条件 ECC”只是历史名称。 |
| `PIT` | Probability Integral Transform | 概率积分变换。把实际价格放进当时的 CDF，得到一个 0 到 1 的相对位置。若预测分布校准良好，长期看这些位置应较均匀；项目用历史 PIT 的跨时点排序来恢复路径依赖。 |
| `AEMO` | Australian Energy Market Operator | 澳大利亚能源市场运营机构。它负责 NEM 的市场与电力系统运行，并发布本项目使用的市场数据和数据模型。 |
| `AEMC` | Australian Energy Market Commission | 澳大利亚能源市场委员会。它制定和修订国家电力市场规则；与负责日常运行和数据发布的 AEMO 不是同一机构。 |
| `NMI` | National Metering Identifier | 全国计量标识，通常用于标识一个计量连接点。主方案说“NMI 能量/边界”时，是借这个标识指代用户与电网交换电量的计量边界，而不是把一串 NMI 编号当作物理设备。 |
| `EMS` | Energy Management System | 能源管理系统，负责协调预测、优化和设备控制。当前项目是离线研究，不建设真实 EMS，也不向设备下发命令。 |
| `forecast` | forecast | 预测，即在结果尚未发生时对未来作出的估计。项目特别要求保存预测是在什么时候产生、什么时候可用的。 |
| `interval-ending` | interval ending convention | “区间结束时刻”口径。例如标记为 10:05 的五分钟价格代表区间 `(10:00, 10:05]`，不是从 10:05 开始的区间。 |
| `issue time` | forecast issue time | 本轮预测对应的发行/决策网格时点。它回答“这份预测属于哪一轮”，不自动证明数据在这一刻已经到达。 |
| `horizon` | forecast horizon | 向前预测多远或第几步。本项目主任务 `h=1...12`，分别对应未来 5 至 60 分钟；“一小时预测”不是把价格聚合成一个小时均价。 |
| `target interval` | target interval being predicted | 被预测的未来五分钟区间。`target interval end` 是该区间的结束时刻，是价格标签的时间主键。 |
| `P10 / P50 / P90` | 10th / 50th / 90th percentile | 预测分布的第 10%、50%、90% 分位点。校准良好时，实际值约有 10% 低于 P10、50% 低于 P50、90% 低于 P90；P10–P90 是名义 80% 区间。 |
| `P01 / P05 / P95 / P99` | 1st / 5th / 95th / 99th percentile | 与 P10/P50/P90 是同一命名规则，只是更靠近分布尾部。越极端的分位点越需要更多尾部样本，不能因为编号更精细就认为更可靠。 |
| `DISPATCHPRICE` | AEMO dispatch price table | AEMO 的五分钟调度价格数据表，主方案从中取得 NSW1 实际 RRP、干预状态及相关价格字段。表名不是一种模型。 |
| `as-published` | as originally published | 按当时最初发布的版本，而不是后来修订后的最终归档版本。它适合研究“当时看到什么”，但是否可重建要通过数据审计。 |
| `LightGBM` | Light Gradient Boosting Machine | 一种基于多棵决策树逐步纠错的机器学习方法。项目用它学习“在当前可见状态下，P5MIN 可能错多少”，而不是让它直接替代全部市场逻辑。 |
| `Schaake shuffle` | Schaake rank shuffle | 用历史事件中各时点的高低排序，把今天各时点独立得到的候选值重新配对成连续路径。它借的是历史排序形状，不必搬用历史价格金额。 |
| `Test` | test set / test period | 最终测试期。模型、校准器、参数和历史模板库在进入 Test 前冻结；Test 用来模拟真正的样本外检验，不能边看结果边调参。 |
| `Predispatch` | pre-dispatch forecast | AEMO 较长视野的预调度预测，原生粒度与 P5MIN 不同。第一阶段只把它作为 120 分钟敏感性和 V2 终端价值的门控候选，不把它伪装成同精度的五分钟预测。 |
| `champion / challenger` | incumbent / candidate | Champion 是当前证据下的默认方法，challenger 是等待公平挑战的候选方法。两者是实验角色，不代表 champion 永远正确或 challenger 一定更先进。 |
| `baseline` | comparison baseline | 基线是候选方法必须公平击败或至少对照的简单参考。强基线能避免把本来就容易获得的改善误算成复杂模型贡献。 |
| `Gross-RRP` | gross value using RRP only | 只考虑 RRP 价格信号的毛价值诊断，不含完整用户费用、损耗和退化，不能称为真实净收益。 |
| `Low / Base / High fee` | low / base / high fee scenarios | 低、中、高三档参数化费用情景，用于检验结论对费用摩擦是否敏感。它们是研究假设，数值必须有来源或显式说明。 |
| `non-anticipativity` | non-anticipativity constraint | 不可预知性约束：在某个动作作出前，如果两个场景拥有相同的已知历史，动作就必须相同。它防止优化器假装提前知道未来会走哪条路径。 |
| `SOC` | State of Charge | 荷电状态，类似电池“电量百分比”。本项目物理方程主要用 kWh 能量状态计算，再把它与 SOC 百分比对应，避免只用百分比掩盖容量单位。 |
| `ramp` | rate or size of change | 相邻时点价格或功率的变化幅度/速度。价格突然从低位跳到高位就是大 ramp；路径模型要能表达这种跳变和恢复。 |
| `manifest` | manifest / inventory record | 产物清单和“账本”，记录数据从哪里来、何时下载、哈希、版本、配置和上游依赖，使结果可以追溯和复算。 |
| `FCAS` | Frequency Control Ancillary Services | 频率控制辅助服务，用于帮助电力系统维持频率。本项目第一阶段不研究 FCAS 收入，只在相关价格或制度状态中保留必要诊断。 |
| `VPP` | Virtual Power Plant | 虚拟电厂，把许多分散资源聚合协调。当前项目没有真实 VPP 接入或结算。 |
| `FRMP` | Financially Responsible Market Participant | 财务责任市场参与者，承担某计量点市场购售电财务责任的主体。当前离线研究不复刻真实 FRMP 合同关系。 |
| `API` | Application Programming Interface | 应用程序接口，让不同软件按约定交换数据或调用功能。第一阶段不建设实时市场或设备 API。 |
| `BMS` | Battery Management System | 电池管理系统，监控电芯、电压、温度、SOC 和安全状态。离线合成电池不等同于真实 BMS。 |
| `PCS` | Power Conversion System | 功率变换系统，负责电池直流与电网交流之间的变换和功率控制。真实 PCS 限制需到生产阶段重新验证。 |
| `SLO` | Service Level Objective | 服务等级目标，例如延迟、可用率或成功率目标。离线运行时间不能冒充生产 SLO。 |
| `uv` | Python project and environment manager | 本项目规定使用的 Python 环境和依赖管理工具，负责锁定解释器、依赖与可复现运行；不是概率模型。 |
| `Git` | version control system | 版本控制系统，用于记录源码变化和历史。实验需要把实际运行代码与 Git 版本或等价源码哈希绑定。 |
| `Python` | programming language | 本项目实现语言，基线版本为 Python 3.11。 |
| `NEMSEER` | third-party NEM data access package | 访问历史 P5MIN 等 NEM 数据的第三方适配器。它方便取数，但 AEMO 原始文件和数据模型才是市场字段事实的权威来源。 |
| `NEMOSIS` | third-party NEM data access package | 访问 AEMO 历史市场数据的第三方适配器，本项目主要用它取得实际价格和市场特征；它同样不是市场规则权威。 |
| `src / tests` | source / test directories | `src/` 通常放实现源码，`tests/` 放自动化测试。主方案首页说明当前仓库尚未进入完整实现阶段。 |
| `commit` | versioned change record | Git 中一次有身份的变更快照。实验记录 commit 后，才能知道结果对应哪版代码。 |
| `SHA-256` | Secure Hash Algorithm 256-bit | 内容指纹算法。文件内容只要变化，哈希通常就会变化，可用于发现原始数据或源码包被替换。它证明内容一致性，不证明内容本身正确。 |
| `HEAD` | current Git revision pointer | Git 当前检出版本的指针。若工作区还有未提交修改，只记录 HEAD 会漏掉实际运行代码差异。 |

## 3. 首见于问题定义、架构和数据章节的术语

| 术语 | 英文全称或直译 | 通俗理解及本项目含义 |
|---|---|---|
| `snapshot` | point-in-time snapshot | 某个决策截点的一张“信息合影”：只含当时已经可见的数据。不同截点要生成不同快照，不能拿今天看到的最终数据回填昨天。 |
| `run` | model or market process run | 一次预测或市场流程的运行。`nominal run time` 是它名义上的时刻，不等于文件已经对研究系统可用。 |
| `available time` | time when data became usable | 数据实际可被决策系统读取和使用的时间，是防未来信息的核心字段。历史上若无法恢复，只能使用有证据、保守且版本化的代理规则。 |
| `proxy` | measurable substitute for an unavailable fact | 代理值。当真实 available time 无法恢复时，用 LASTCHANGED、文件时间和保守延迟等证据近似；必须标成代理，不能写成官方事实。 |
| `decision cutoff` | information cutoff for a decision | 本轮决策冻结信息集的截止时刻。所有输入的 available time 都必须不晚于它。 |
| `outcome available time` | time when the result became known | 实际价格或完整路径何时已经揭晓。它决定一条历史样本何时可以用于训练、校准或模板库。 |
| `ingestion time` | local ingestion time | 数据真正被本地系统抓取或写入的时间。它适合未来在线采集，历史档案通常无法完整恢复。 |
| `first-seen` | first observed by the local system | 本地系统第一次看见某条数据的时间，是比文件名或名义运行时间更直接的实时可见性证据。 |
| `NEM` | National Electricity Market | 澳大利亚国家电力市场。本文涉及的是 NEM 中的 NSW1，不包括西澳 WEM。 |
| `UTC` | Coordinated Universal Time | 协调世界时，全球统一时间基准。项目通过显式时区转换，避免把本地钟表时间误当作市场时间。 |
| `AEST` | Australian Eastern Standard Time | 澳大利亚东部标准时间，固定 UTC+10。主方案的 NEM 市场层全年按 AEST，不随夏令时变化。 |
| `Australia/Sydney` | IANA timezone for Sydney | 悉尼民用时区，会随夏令时在 UTC+10 与 UTC+11 间切换。站点日历可以使用它，但进入市场层前必须转成固定 AEST。 |
| `INTERVENTION` | intervention run indicator | AEMO 数据中的干预运行标志。主方案把 `0` 用于定价运行标签，并保留干预区间作分层和敏感性，不能把不同运行语义混在一起。 |
| `A$/MWh` | Australian dollars per megawatt-hour | NEM 批发价格常用单位。换成 A$/kWh 时除以 1000；若遗漏这一步，现金流会放大 1000 倍。 |
| `A$/kWh` | Australian dollars per kilowatt-hour | 用户侧进口、出口和电池结算在本项目中的价格单位，便于与 kWh 电量直接相乘得到澳元。 |
| `MW / MWh` | megawatt / megawatt-hour | MW 是功率，MWh 是能量；与 kW/kWh 的关系都是 1000 倍。不能把功率与能量混用。 |
| `ROP` | Regional Original Price | 区域原始价格字段，可理解为某些价格覆盖或调整前的原始区域价格。主标签仍是 RRP，不能用 ROP 偷换。 |
| `APC / APCFLAG` | Administered Price Cap / related flag | 管制价格上限及相关状态标志，用于识别市场进入管制价格状态。具体字段取值必须跟随所用 AEMO 数据模型版本。 |
| `as-of` | as known at a stated time | “截至某一时刻已知”的口径。as-of 回放不是简单按事件日期过滤，而是逐字段判断它在当时是否已经可用。 |
| `bucket` | grouped interval or category | 把连续值或很多细时段合并成较粗的组，例如 lead bucket、月份桶或价格状态桶，以增加每组样本量。边界只能用训练/验证期冻结。 |
| `Point-in-Time` | information valid at a historical time | 强调历史回放要站在当时视角。注意：主方案不把它缩写成 PIT，以免与 Probability Integral Transform 混淆。 |
| `raw` | raw data layer | 未经业务变换的原始数据层。原始对象应不可变，后续标准化、特征和模型产物另行分层。 |
| `calibration` | probability calibration | 概率校准，使“预测 20% 的事件”长期约有 20% 发生。它不同于让点预测更接近实际值，也不是单纯把区间变宽。 |
| `settlement` | settlement / accounting | 按实际能量、价格和费用计算现金流。预测场景用于决策，最终回测结算必须使用冻结价格版本下的实际结果。 |
| `pinball loss` | quantile loss | 分位数预测的专用损失。低估和高估受到不对称惩罚，因此可以分别训练 P10、P50、P90，而不是只评价平均误差。越低通常越好。 |
| `Brier score` | squared probability error | 二元事件概率误差，例如负价预测概率与实际是否负价之间的平方差。越低越好，但还要结合可靠性和事件样本量看。 |
| `regret` | value lost relative to a benchmark | 相对某个更强基准少获得的价值。项目常用候选策略相对完美预知基准的差额衡量还有多少机会未捕获。 |
| `dispatch cycle` | one dispatch calculation interval | 一次调度计算周期。主方案所述 P5MIN 一小时包含 12 个五分钟 dispatch cycles。 |
| `REGIONID` | region identifier field | AEMO 数据中的区域字段，用来区分 NSW1、QLD1、VIC1 等区域。 |
| `GST` | Goods and Services Tax | 澳大利亚商品及服务税。AEMO 公布的批发报价是否含 GST 必须按官方字段定义理解，不能直接当作用户含税电价。 |
| `LASTCHANGED` | source record last-changed timestamp | 记录最近被源系统修改的时间，可作为历史可见性的代理证据之一，但不等于本地第一次收到数据的时间。 |
| `SLA` | Service Level Agreement | 服务等级协议，通常承诺服务发布时间或可用率。主方案明确不能把 LASTCHANGED 未经验证地称为 AEMO 官方发布 SLA。 |
| `DISPATCHREGIONSUM` | dispatch regional summary table | AEMO 的区域调度汇总表，包含区域供需等状态；在本项目中只作为通过可见性审计的特征来源。 |
| `P5MIN_REGIONSOLUTION` | P5MIN regional solution table | P5MIN 中的区域预测结果表，可提供未来区域需求、价格等短期状态。字段必须先按数据模型审计。 |
| `DISPATCHINTERCONNECTORRES` | dispatch interconnector results table | 调度联络线结果表，用来描述区域之间实际潮流、限额等状态。 |
| `P5MIN_INTERCONNECTORSOLN` | P5MIN interconnector solution table | P5MIN 的联络线预测结果表，用于构建决策时可见的未来网络辅助特征。 |
| `flow / limit / headroom` | power flow / limit / remaining margin | Flow 是联络线当前潮流，limit 是允许边界，headroom 是距离边界还剩多少空间。可类比道路当前车流、道路容量和剩余通行余量。 |
| `PV` | Photovoltaic | 光伏发电。S2 合成站点中要分别记录负荷、PV、电池和 NMI 进出口，防止同一电量重复计价。 |
| `hash` | content hash | 内容指纹的统称。manifest hash、源码 hash 和数据 hash 用来绑定具体内容，而不是只靠容易变化的文件名。 |
| `lineage` | data lineage | 数据血缘，说明一条预测、路径、动作或收益是由哪些原始文件、快照、模型和配置生成的。 |
| `schema` | data structure contract | 数据结构契约，规定字段名称、类型、单位、主键和必填规则。共享 schema 能防止不同模块对同一字段各自理解。 |
| `quality flag` | machine-readable quality marker | 质量标志，用于记录缺失、回退、陈旧、重建、冲突或降级等状态，避免只留下一个看似正常的数值。 |
| `inclusion mask` | rule indicating which samples enter a comparison | 样本纳入掩码，明确哪些 issue/target 行进入评价。模型与基线只有使用同一 mask，比较才公平。 |
| `revision` | later revision of a record or forecast | 后续修订。P5MIN 对同一目标会不断修订，实际价格也可能修订；项目必须保存轨迹并冻结主价格版本。 |
| `bootstrap` | resampling-based uncertainty estimation | 重抽样估计不确定性的方法。时间序列不能逐行随意抽，本项目按完整日、多日块或事件块重抽。 |
| `winsorize` | replace extreme values with boundary values | 把极端值压到某个上下界。主方案禁止为了让指标好看而对极端 RRP 做这种处理。 |
| `asinh` | inverse hyperbolic sine transform | 一种能压缩大正值和大负值、同时保留零附近结构的数值变换。模型内部可以使用，但报告和结算必须还原原始价格尺度。 |
| `signed-log` | sign-preserving logarithmic transform | 保留正负号的对数型变换，用来压缩极端数值；同样不能改变最终阈值、评价和结算口径。 |
| `off-by-one` | one-step indexing error | 时间或数组错一格。例如把 `(10:00,10:05]` 的价格错接到下一段，会造成五分钟级未来信息泄漏。 |
| `Train` | training period | 训练期，用来拟合模型参数和训练期统计。 |
| `Validation` | validation period | 验证期，用来选择特征、超参数、窗口和候选方法；不能用最终 Test 结果替代。 |
| `Calibration` | calibration period | 校准期，用来拟合分位数、覆盖率或事件概率的校准参数。它与上面的 calibration 方法含义一致，这里强调数据切分角色。 |
| `context` | contextual state | 上下文或条件状态，例如时段、季节、当前 P5MIN 曲线和网络状态。J3 用当时可见 context 找相似历史。 |
| `embargo` | time gap between data splits | 数据切分之间故意留出的隔离带，防止预测窗口或标签跨越边界，导致相邻集合互相泄漏。 |
| `untouched holdout` | never-inspected holdout set | 从未用于调参或看结果的保留集。若 Test 被反复查看，它就不再“干净”，需要新的 untouched holdout 才能恢复强结论。 |
| `rolling-origin` | expanding or rolling historical origin evaluation | 沿时间向前移动预测起点，每个起点只使用此前数据拟合和预测。它比随机切分更接近真实上线过程。 |

## 4. 首见于特征、概率预测和校准章节的术语

| 术语 | 英文全称或直译 | 通俗理解及本项目含义 |
|---|---|---|
| `slot` | time slot | 一天内的固定五分钟位置。一天理论上有 288 个五分钟 slot；相同时段的价格行为可能相似。 |
| `regime` | market regime / state | 市场状态分组，例如普通、负价、高价或高波动状态。它是分析标签，不代表市场真的存在清晰不变的“制度”。 |
| `rolling median` | rolling-window median | 只用过去一段窗口计算的中位数，比均值不容易被尖峰拉偏。窗口必须严格向后看。 |
| `MAD` | Median Absolute Deviation | 中位绝对偏差，一种稳健波动度量。先找中位数，再看各值偏离它多少，较少受单次极端价影响。 |
| `episode` | contiguous event episode | 一段连续或按规则合并的事件，例如一轮持续负价或同一次尖峰。多个五分钟窗口可能只是同一 episode，不是多个独立事件。 |
| `QLD1 / VIC1` | Queensland / Victoria region identifiers | 昆士兰和维多利亚区域代码。它们只能作为决策时可见的辅助特征，不能成为 NSW1 标签或结算价格。 |
| `binding / near-binding` | binding / nearly binding constraint | 约束已经卡住或接近卡住。可类比道路已满载或接近容量上限，可能影响区域间电力流动和价格。 |
| `missing` | missing data | 数据缺失。关键 RRP、P5MIN、SOC 和费用不得静默补零。 |
| `imputation` | missing-value imputation | 对允许填补的普通特征估算缺失值。填补规则只能在训练期拟合，并留下缺失和回退标志。 |
| `fallback` | explicit fallback | 主方法条件不满足时，按预先冻结的顺序退回更简单方法。回退不是吞掉错误；非法输入和血缘损坏仍应失败。 |
| `reconstructed` | reconstructed from historical evidence | 根据历史文件或代理规则重建，而非真实在线采集。必须留下标志，不能冒充原始 first-seen 事实。 |
| `sin / cos encoding` | sine/cosine cyclical encoding | 用正弦和余弦表示小时或季节周期，使 23:55 与 00:00 在数学上仍然相近。 |
| `OOD` | Out of Distribution | 分布外状态，即当前输入明显不同于训练历史。项目先把它当诊断信号，只有验证证明有效后才允许自动扩宽预测区间。 |
| `anchor` | forecast anchor | 锚点。本项目用当时最新可见 P5MIN 作为基础预测，再预测其误差；像先有官方路线，再估计它可能偏多少。 |
| `residual` | actual minus forecast residual | 残差，固定定义为“实际 RRP − P5MIN 锚点”。正值表示 P5MIN 低估，负值表示 P5MIN 高估。 |
| `quantile` | quantile / percentile point | 分位数，回答“某比例的可能结果不超过什么值”。P50 是中位数，不一定等于均值。 |
| `crossing` | quantile crossing | 分位数交叉，例如模型给出的 P10 高于 P50。它违反分布顺序，必须修复并保留原始交叉率作模型稳定性诊断。 |
| `CDF` | Cumulative Distribution Function | 累积分布函数。给定价格 `x`，CDF 告诉我们“实际价格不高于 x 的概率”；完整 CDF 才能生成任意分位点和概率场景。 |
| `pooled-horizon` | pooled model across horizons | 把多个 horizon 的样本放进同一个模型，并把 `horizon_step` 当特征。这样共享数据量，同时仍允许不同未来步有不同误差。 |
| `binary classification` | two-class classification | 预测事件发生或不发生，例如是否负价。输出需要校准成概率，不能只给 0/1 标签。 |
| `ensemble` | combination of multiple models | 组合多个模型或预测成员。项目只在 Validation 选择组合规则，不能按 Test 收益临时调权重。 |
| `monotone rearrangement` | monotonic rearrangement | 把交叉的分位数重新排序为从低到高，确保 P10 不高于 P50、P50 不高于 P90。修复前的交叉仍需保存作诊断。 |
| `isotonic projection / calibration` | monotonic projection / calibration | 在保持单调的约束下，尽量小幅调整一组值或概率。可理解为把“乱序台阶”拉回不下降的台阶。 |
| `floor / cap` | market price floor / cap | 目标时点有效的市场价格下限和上限，是分布硬支持边界。它们来自规则版本，不是为了让模型好看而随意截断。 |
| `PCHIP` | Piecewise Cubic Hermite Interpolating Polynomial | 保形分段三次插值。它在已知分位点之间画较平滑的曲线，同时比普通高阶样条更不容易产生不合理振荡和越界。 |
| `EVT` | Extreme Value Theory | 极值理论，专门研究尾部极端事件。它需要足够样本和稳定阈值；第一阶段只把它作为 challenger。 |
| `GPD` | Generalized Pareto Distribution | 广义帕累托分布，EVT 中常用于拟合超过高阈值的尾部。样本不足时容易不稳，不能自动优于经验尾部。 |
| `stress package` | separate stress-scenario bundle | 人工压力情景包，用来测试系统承受极端价格的表现。它没有客观概率权重，不能混进期望收益、CVaR 或概率评分。 |
| `quantile mapping` | quantile-based calibration mapping | 根据历史覆盖偏差调整预测分位点，使名义分位数与实际频率更一致。映射只能用合法校准期拟合。 |
| `conformalized quantile adjustment` | conformal quantile correction | 用时间外误差给预测区间增加数据驱动的修正，目标是改善覆盖率。它仍需遵守时序切分，不能保证所有细分状态都精确覆盖。 |
| `beta calibration` | beta-family probability calibration | 一种把原始事件概率重新映射为更可靠概率的方法，适合校准二元事件模型；参数在 Calibration 期拟合。 |
| `WIS` | Weighted Interval Score | 加权区间评分，把多个预测区间的宽度和漏覆盖惩罚合成一个分数。越低越好，能同时约束“太宽”和“漏掉实际值”。 |
| `CRPS` | Continuous Ranked Probability Score | 连续排序概率评分，综合比较完整预测分布与最终实际值。可把它理解为“对所有阈值的概率误差做整体汇总”，越低越好。 |
| `reliability` | probability reliability / calibration | 可靠性，检查预测概率与长期实际发生频率是否一致。例如所有标成 30% 的负价事件是否约有 30% 发生。 |
| `MAE` | Mean Absolute Error | 平均绝对误差，计算点预测与实际值差的绝对值再取平均。越低越好，但不描述完整概率分布。 |
| `RMSE` | Root Mean Squared Error | 均方根误差，对大误差惩罚更重，因此对价格尖峰特别敏感。 |
| `Bias` | mean signed error | 有符号平均误差，用来看模型是否系统性高估或低估；正负方向必须结合残差定义解释。 |
| `median AE` | median Absolute Error | 绝对误差的中位数，描述“典型一次”误差，较少被少数尖峰支配。 |

## 5. 首见于联合价格路径章节的术语

| 术语 | 英文全称或直译 | 通俗理解及本项目含义 |
|---|---|---|
| `marginal distribution` | marginal probability distribution | 单个 horizon 自己的概率分布。例如只看 t+15 分钟可能出现哪些价格，不说明它与 t+10、t+20 如何一起变化。 |
| `joint path / joint distribution` | joint multi-step path / distribution | 同时描述 12 个未来时点如何共同变化。储能关心负价持续多久、尖峰何时来，因此只看 12 个独立边际还不够。 |
| `Copula` | dependence structure separated from marginals | 一种把“每个时点各自长什么样”和“它们如何联动”分开建模的数学工具。ECC 和 t-Copula 都在处理依赖结构。 |
| `inverse CDF` | inverse cumulative distribution function | 给定 0 到 1 的概率位置，反查对应价格。路径工厂用它从当前 CDF 生成等概率候选值。 |
| `independent permutation` | independent random permutation | 每个 horizon 分别随机打乱候选值，再横向连成路径。J0 用它构造“不特意加入时间依赖”的零基线。 |
| `residual block` | multi-step historical residual block | 某个历史起点后连续 H 步的完整误差向量。J1 把整块加到当前 P5MIN 锚点上，保留历史误差形状。 |
| `randomized PIT` | randomized Probability Integral Transform | 当 CDF 在某个价格上有点质量时，不把所有相同实际值挤在一个 PIT 点，而是在该概率跳跃区间内稳定随机化。 |
| `rank` | ordinal position | 排名，只关心谁更高、谁更低，不关心金额差多少。J2/J3 用历史 PIT rank 连接今天的候选价格。 |
| `kernel / bandwidth` | similarity kernel / bandwidth | J3 中把历史状态与当前状态的距离变成选择倾向。Bandwidth 越小越挑“很像”的历史，越大则接受更宽的邻域。 |
| `market day` | configured AEST research-day grouping | 用于限制同一天模板贡献的研究分组。它必须显式配置，不能把悉尼夏令时日期未经核验地称为官方市场日。 |
| `cold start` | insufficient-history start-up condition | 历史模板还不够时的启动阶段。项目按冻结路线从 J3 退到 J2、J1 或 J0，而不是复制少数模板凑数。 |
| `support` | amount and diversity of usable evidence | 可用历史支持度，不只看模板行数，还看唯一起点、市场日、独立事件、年龄和集中度。100 行可能仍只是同一次尖峰的重复视角。 |
| `family` | compatible model/distribution method family | 一套兼容的预测 CDF/PIT 方法规范。不同月份可以是同 family 的不同快照；跨 family 混用历史 PIT 默认禁止。 |
| `Energy Score` | multivariate probabilistic score | 多变量概率评分，衡量整条预测路径集合与实际路径的整体距离，类似多维版本的 CRPS。越低通常越好。 |
| `Variogram Score` | dependence-sensitive multivariate score | 更关注不同时点之间差值是否合理，因此能补充 Energy Score 对依赖结构不够敏感的部分。越低通常越好。 |
| `scenario reduction / compression` | reduce the number of scenarios | 用较少代表路径近似原场景集，以降低求解成本。压缩后场景通常不再等权，必须重新检查边际、尾部和首动作。 |
| `scenario batch / bundle` | one versioned group of scenarios | 同一决策时点、同一方法和配置生成的一批场景。概率场景包与无概率权重的压力包必须分开。 |
| `open-loop` | plan fixed before future observations | 开环计划，未来 12 步动作预先固定，对所有场景相同。它保守、容易验证，但不能利用以后新观察到的信息调整计划。 |
| `recourse` | later action adapting to observations | 补救/再决策能力：未来信息逐步揭晓后，后续动作可以调整。允许怎样调整必须受 non-anticipativity 约束。 |

## 6. 首见于储能优化和终端价值章节的术语

| 术语 | 英文全称或直译 | 通俗理解及本项目含义 |
|---|---|---|
| `scenario tree` | branching representation of scenarios | 把多条未来路径按“到当前阶段为止看到的共同前缀”组织成树。场景只有在信息真正分开后，动作才允许分开。 |
| `root node / leaf node` | first shared node / final scenario node | 根节点是当前所有场景共用的决策点；叶节点代表一条完整未来路径的末端。每轮真正执行的是根节点第一步。 |
| `MILP` | Mixed-Integer Linear Programming | 混合整数线性规划：目标和约束主要是线性的，但含 0/1 等整数变量。本项目用二进制变量禁止同时充放电。 |
| `LP` | Linear Programming | 线性规划，变量连续且目标/约束线性。LP 通常比 MILP 容易求解，但不能自动表达所有开关和方向逻辑。 |
| `overlay` | additional market-control layer | 叠加控制层。S2 先满足本地价值和备用，再让市场优化使用剩余功率、能量与 NMI 余量；两层动作必须分别记账。 |
| `cash flow` | money received minus money paid in an interval | 某个五分钟区间真实或场景化的收入与成本流。价格乘实际进口/出口电量后，还要扣费用、退化和辅助成本。 |
| `degradation` | battery wear caused by use and aging | 电池退化。第一阶段没有真实电芯数据，因此用显式、参数化的吞吐成本做敏感性，不能把它说成真实保修成本。 |
| `CVaR` | Conditional Value at Risk | 条件风险价值。这里关注最差一小部分场景中的平均损失，而不只看平均收益；例如 `α=95%` 时关注最坏约 5% 尾部。 |
| `safe counterfactual` | pre-defined safe comparison policy | 预先冻结的安全反事实策略，用来计算候选动作相对“不冒险做法”的增量损失。不能事后为每个场景挑一个最有利安全动作。 |
| `nested CVaR` | dynamically nested Conditional Value at Risk | 把风险度量按多阶段决策递归嵌套，追求动态时间一致性。第一阶段只做根节点静态 CVaR，每五分钟重算，不声称实现 nested CVaR。 |
| `solver` | optimization solver | 真正求解 LP/MILP 的软件。模型层描述问题，solver 搜索可行且尽量优的解。 |
| `status / runtime / gap / node count` | solve status / elapsed time / optimality gap / search nodes | 分别表示求解是否成功、耗时、当前解离理论最优界还有多远、搜索了多少分支节点。不能只保存一个动作而丢掉求解质量。 |
| `terminal value` | value assigned to end-of-horizon inventory | 终端价值，给一小时窗口结束时剩余电量估一个“未来机会成本”。它帮助避免临近窗口末端盲目放空，但不是当期已经实现的收入。 |
| `artifact` | versioned research output | 可版本化、可引用的研究产物，例如模型、价值表、场景批次或报告。它应带配置、血缘和内容身份。 |
| `SOS2` | Special Ordered Set of type 2 | 优化器中表达分段线性插值的结构，通常只允许两个相邻格点同时起作用，避免价值曲线跨越中间点走不真实“捷径”。 |
| `salvage value` | residual value at a boundary | 边界剩余价值。这里不是“报废残值”，而是给延续优化末端剩余电量一个共同、版本化的价值处理。 |
| `rollout policy` | policy simulated forward through time | 把一条可实际执行的固定策略向未来模拟，用它估算延续价值。相比完美预知优化，rollout 更保守但更接近可实施行为。 |
| `terminal salvage approximation` | approximate continuation value at the horizon | V1_v0 的定位：利用历史训练数据近似窗口外剩余电量价值。它是决策辅助，不是未来现金流承诺。 |
| `PnL` | Profit and Loss | 盈亏。回测 PnL 只累计实际执行五分钟区间的现金流，并在连续段终点按共同规则最多做一次期末调整。 |

## 7. 首见于结算、评价、工程和未来演进章节的术语

| 术语 | 英文全称或直译 | 通俗理解及本项目含义 |
|---|---|---|
| `import / export` | grid import / grid export | 从电网买入/向电网送出。两者要使用 NMI 边界上的实际 kWh，不能把电池内部能量直接当成结算电量。 |
| `adders / adjustments` | price additions / adjustments | 在 RRP 换算价上叠加的进口费用或出口调整。每一项必须声明单位、正负含义、适用方向、来源和生效期。 |
| `outcome` | realized result | 实际发生的结果，例如真实五分钟 RRP、负荷或 PV。优化时用 forecast，区间结束后才允许用 outcome 更新状态和结算。 |
| `backtest / replay` | historical simulation / chronological replay | 回测或历史重放：按真实时间顺序，只释放当时已可见的数据，执行策略并用随后发生的实际结果更新状态和结算。它不是离线最优直接套历史。 |
| `pricing run / physical run` | pricing calculation / intervention physical dispatch | 干预情形下可能分别用于定价和物理调度的运行语义。主标签和状态特征必须按字段定义区分。 |
| `oracle` | method allowed to know future outcomes | “神谕”基准，允许读取未来实际结果，用来估计机会空间或误差来源。它不是可部署策略。 |
| `benchmark` | comparison reference | 比较基准。它可能是简单策略、官方预测或完美信息诊断；只有证明可行域足够宽时才能称严格上界。 |
| `pre-registration` | freezing choices before final evaluation | 预注册，即在查看最终 Test 结果前写明主指标、阈值、参数、回退和判定规则，减少事后挑选有利结果。 |
| `Go / No-Go` | proceed / stop decision gate | 阶段验收门：Go 表示证据足够进入下一步，No-Go 表示修复、回退、简化或停止强结论，不一定代表整个项目失败。 |
| `deterministic` | single assumed future | 确定性方法，只用一条价格曲线或一个代表值优化，例如 P50。 |
| `stochastic` | multiple weighted possible futures | 随机优化方法，同时考虑多条带权场景及其风险。这里的“随机”不是随便行动，而是显式建模不确定性。 |
| `multistage` | decisions made in several information stages | 多阶段决策，随着信息逐步揭晓允许后续动作分叉，但每一步都不能提前读取未来后缀。 |
| `optimistic relaxation` | deliberately loosened optimistic model | 为诊断而放松现实信息约束，得到偏乐观结果。O2 可作上界参考，不能称为可实施策略。 |
| `PR-AUC` | Area Under the Precision-Recall Curve | 精确率—召回率曲线下面积，常用于负价、尖峰等稀有事件。事件太少时数值很不稳定，必须同时报告样本和 episode 数。 |
| `LCB` | Lower Confidence Bound | 置信区间下界。非劣效检验关心最保守仍可能达到的差值，而不是只看均值是否大于零。 |
| `moving / block bootstrap` | moving-block / block resampling | 按连续时间块重抽样，保留部分时序相关性。项目不会把每个五分钟行当成相互独立。 |
| `Shapley-like` | contribution attribution inspired by Shapley values | 通过改变组件加入顺序来估计各组件贡献，帮助发现交互项。它是敏感性归因，不会自动给出唯一“真实功劳”。 |
| `URI` | Uniform Resource Identifier | 产物位置标识，可指向文件、对象存储或其他资源。manifest 应绑定具体 URI 和内容身份，不能只读取“最新文件”。 |
| `CLI` | Command-Line Interface | 命令行接口，例如 `audit-data`、`run-backtest`。它是明确的工程边界，负责校验输入、报告领域错误和触发可复现流程。 |
| `notebook` | interactive computational document | 交互式分析笔记本，适合探索，但不能成为唯一产物；正式实验还需配置、长表、manifest 和可重放命令。 |
| `Polars / PyArrow / DuckDB` | columnar-data processing tools | 候选列式数据处理工具，适合按月处理大量五分钟长表。它们只是候选技术栈，尚未安装不等于已有能力。 |
| `scikit-learn` | Python machine-learning library | 候选机器学习与校准工具库，可提供预处理、评价和部分模型。具体依赖需通过 `uv add` 引入。 |
| `pytest` | Python testing framework | Python 自动化测试框架，用于验证时间对齐、概率、能量守恒、回放复现等契约。 |
| `golden replay` | fixed reference replay | 固定一个小历史窗口及预期结果，升级依赖或修改代码后重跑对比，用来尽早发现行为漂移。 |
| `BESS` | Battery Energy Storage System | 电池储能系统。主方案中的 10 kW / 20 kWh BESS 是合成研究资产，不代表真实项目。 |
| `Graph model` | graph-based model | 把区域、设备或关系表示成节点和边的模型。只有已证明简单基线瓶颈后，才考虑这种复杂模型。 |
| `Flow model` | normalizing-flow-style probabilistic model | 此处指概率建模中的流式生成模型，通常把简单分布可逆变换成复杂分布，不是联络线的 power flow。它属于未来候选。 |
| `t-Copula` | Student-t copula | 用多元 t 分布刻画变量依赖的 Copula，能够表达一定尾部共同极端性；同样必须在相同信息集下与简单方法公平比较。 |
| `SOH` | State of Health | 电池健康状态，描述相对新电池的容量、功率和老化程度。第一阶段没有真实 SOH 数据。 |
| `Shadow mode` | observe and recommend without control | 影子模式：系统在线计算和记录建议，但不控制设备，用于验证真实数据与延迟。 |
| `Canary` | limited trial on a small scope | 金丝雀试运行：只在很小范围启用，以限制潜在故障影响。 |
| `Limited Auto` | limited automatic control | 受严格范围、功率和安全规则限制的自动控制阶段，晚于 Shadow 和 Canary。 |
| `OT` | Operational Technology | 直接连接和控制现场设备的运行技术网络。它比普通离线 IT 分析有更高安全、权限和变更要求。 |
| `YAML` | YAML Ain't Markup Language | 人类可读的配置格式。附录 A 只是配置骨架，其中 `REQUIRED_*` 是必须替换的占位符，不是允许默认为零的值。 |
| `Etc/GMT-10` | fixed-offset IANA timezone name | IANA `Etc/GMT` 命名的正负号与直觉相反，`Etc/GMT-10` 表示固定 UTC+10。实现仍需自动化测试，不能仅凭字符串猜时区。 |

## 8. 项目内部编号速查

## 9. 最容易混淆的九组概念

| 容易混淆 | 一句话区分 |
|---|---|
| `kW` 与 `kWh` | kW 是速度，kWh 是累计数量；类似“车速”与“行驶里程”。 |
| `RRP` 与用户进出口价 | RRP 是批发区域基准；用户价还要除以 1000 并叠加进口费用或出口调整。 |
| `P5MIN` 与概率预测 | P5MIN 提供点预测锚点；P10/P50/P90、CDF 和事件概率由本项目的历史残差模型与校准产生。 |
| `issue time` 与 `available time` | issue time 说明属于哪轮预测，available time 才决定当时能否真的使用。 |
| `Point-in-Time` 与 `PIT` | Point-in-Time 是“站在历史当时看数据”；PIT 是实际值在预测 CDF 中的概率位置。 |
| `P10/P50/P90` 与完整 `CDF` | 三个分位点只是三根标尺；完整 CDF 才描述整条分布和尾部。 |
| 边际分布与联合路径 | 边际回答每个时点各自可能多少；联合路径回答这些时点会怎样一起发生。 |
| `SOC` 与电池能量 | SOC 是百分比状态，kWh 是实际能量；物理守恒最终要落到 kWh。 |
| `terminal value` 与已实现 `PnL` | terminal value 只帮助当前优化判断窗口外机会；已实现 PnL 只来自真实执行区间和共同期末调整。 |
